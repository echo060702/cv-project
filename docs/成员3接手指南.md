# 成员3：E/F、独立评估、分析与课程整合

先读 `00_交接说明_两位成员先读.md`；基线结果与口径见 `docs/G_A正式基线结果与分析.md`。成员1 已完成 G/A 六次正式 run，成员2 负责 B/C/D。你负责 E/F 各 3 种子（6 次）与独立评估整合，可以立即开发 `team_eval.py` 与报告结构。

## 现在开始

1. 解压后先 `tools.package_team --verify .`、21 项自测、`tools.verify_data_handoff`；读数据审计报告与结果分析稿，不重划分数据、不重跑 G/A。
2. 用 `cvdetect.inference.load_detector` 加载 `runs/baselines/<run>/best.pt` 验证接口：模型输入未归一化 [0,1] RGB，内部做归一化与残差，`sigmoid(logit)` 为 AI 概率；输出应为 1,200 行 dev 预测。
3. 开发 `team_eval.py` 与统计/作图代码，输入正式 checkpoint、冻结清单与评价条件，输出逐图预测与可复算指标；工程验证可用 synthetic fixture，但不得与正式成绩混用。
4. 用统一入口跑 E/F 种子 17，再补 29/43，共 6 次；配方与成员2 完全一致，E/B 与 F/D 严格同容量。

## 正式评估与分析

- dev 阶段确定单/五 patch 方案并保存选择摘要；冻结候选 checkpoint、阈值 0.5、种子与压力条件后，才对 holdout 做一次确认。
- 主表为干净单 patch Accuracy；附每类 precision/recall、ROC-AUC、混淆矩阵与三种子均值/标准差。
- 压力条件：JPEG Q90/70/50/30、同区域 0.5 倍缩小再恢复；两类同条件、配对逐图，扰动顺序与插值固定。
- 种子17 按 `group_id` 做配对 bootstrap，报告 Accuracy 差值 95% 区间；不要把三个种子当三倍独立样本。
- 必须分析审计发现的偏差：真实全 JPEG、AI 全 PNG、813 张短边<224、分辨率与颜色模式差异。元数据模型只能用 train 拟合、dev 评价；不得把路径或文件名当视觉特征。
- 报告成本（六次基线每 epoch 中位 121–140 s、峰值显存约 1.94 GB）、错误样本与压缩导致的翻转案例；每个数字绑定源码/配置/划分/权重哈希与逐图结果，登记到 `docs/结果记录模板.csv`。

把 `results/evaluation_freeze.json` 与模型选择摘要交成员2；成员2 生成全量有标签清单并训练最终模型。你按冻结推理方法对 `data/official/dataset/test` 生成预测，用 `data/raw/sample_submission.csv` 核对 ID/列/行数，label 必须为整数 0 或 1（模板 0 是占位，不是测试标签，不按公开类别比例强制平衡）。
