# 队友交付流程：提交实验并发布权重

适用对象：成员2（B/C/D 九次）、成员3（E/F 六次）。成员1（G/A 六次）已完成，可作为模板。
本流程保证：结果可复现、权重不进 git、每次发布有标签与校验值。

## 0. 前置

```bash
git clone https://github.com/echo060702/cv-project.git
cd cv-project
python -X utf8 -m unittest discover -s tests -v          # 21 项自测应通过
```

G/A 权重从 Release 取（仅用于对照，不必重跑）：

```bash
curl -L -o checkpoints.zip https://github.com/echo060702/cv-project/releases/download/v1.0-weights/checkpoints.zip
sha256sum checkpoints.zip    # befe02f3d1269a814a0ed803f4a2284be850f2a6a01f0cfefc948ffdf1bee687
unzip -o checkpoints.zip -d .
```

图像按 `docs/仓库说明_数据与权重获取.md` 第 2 节获取到 `data/official/dataset/{train,test}/`，
然后 `python -X utf8 -m tools.verify_data_handoff --output validation/received.json` 逐图校验。

## 1. 开分支

```bash
git checkout -b member2/bcd     # 成员3 用 member3/ef
```

不要直接往 `main` 提交；完成后发 PR，由组内另一人看一眼再合并。

## 2. 跑实验（冻结配方，不得单组改预算）

```bash
# 成员2：B/C/D；成员3：E/F。种子 17 → 29 → 43 顺序跑。
python -X utf8 -m cvdetect.train --config configs/B.json --adapter team_data:build_loaders --seed 17 --output runs/baselines/B_seed17 --device cuda
```

中断后恢复：同一命令加 `--resume runs/baselines/B_seed17/last.pt`，只支持完整 epoch 边界，源码/配置/数据版本必须不变。

## 3. 汇总与核验（不训练，只重放 dev）

```bash
python -X utf8 -m tools.summarize_baselines --experiments B C D --seeds 17 29 43 \
  --runs runs/baselines --output results/bcd --verify-predictions --device cuda
```

`--experiments/--seeds` 可任意指定组号与种子（2026-11-22 起支持；G/A 默认行为不变）。
它会重载每个 `best.pt`、重放 1,200 张开发集，与日志逐图比对；不一致会直接报错。

## 4. 提交哪些、不提交哪些

| 提交 | 不提交 |
|---|---|
| `runs/baselines/<组>_seed<种子>/` 下 `config.json` `metadata.json` `environment.json` `metrics.jsonl` `dev_predictions.csv` | `*.pt`（`.gitignore` 已排除，走 Release） |
| `results/bcd/`（`per_run.csv` `summary.csv` `baseline_summary.json` 曲线） | `data/official/`（官方图像） |
| `docs/` 结果分析、`tasks.json` 中对应任务状态改为“已完成” | `dist/*.zip`、虚拟环境、`__pycache__` |

```bash
git add runs results docs tasks.json
git status --porcelain                 # 确认没有 .pt 被暂存
git commit -m "B/C/D 三种子正式结果与汇总"
git push -u origin member2/bcd
```

## 5. 发布权重（GitHub Release）

```bash
# 一条命令打包 + 计算 SHA256（缺失某个 run 会直接报错）
python -X utf8 -m tools.pack_checkpoints --experiments B C D --seeds 17 29 43 \
  --output dist/bcd_checkpoints.zip --release-body dist/bcd_release.md
```

然后在 GitHub 网页操作（**必须先建 draft**，本仓库开启了 release immutability）：

1. Releases → Draft a new release → 新建 tag，例如 `v1.1-bcd`（分支选 `main`）
2. 上传 `dist/bcd_checkpoints.zip`
3. 正文粘贴 `dist/bcd_release.md` 的内容（已含文件表、大小、SHA256、用法）
4. **Publish release**

注意：tag 名一旦被发布过就永久绑定，重发必须换新 tag（如 `v1.1-bcd` → `v1.2-bcd`）；
对已发布 Release 再上传附件会报 `422 Cannot upload assets to an immutable release`。

## 6. 合并与交接

- PR 标题写清楚组号、种子数、汇总指标；描述附 `results/bcd/summary.csv` 内容。
- 合并后把 tag、Release 链接写进 `docs/成员3接手指南.md`（或对应结果章节），供论文与展示引用。
- 成员3 在开发集上完成 E/F 后，按 `docs/最终重训与结果追溯.md` 走评估冻结与最终模型，不在此流程内。

## 7. 常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| `Authentication failed` | 本机 schannel 故障 | 用 `C:\Program Files\Git\cmd\git.exe -c http.sslBackend=openssl push ...` |
| `422 Cannot upload assets...` | 对已发布 Release 传附件 | 建 draft 再传，最后 publish |
| `422 tag_name was used by an immutable release` | 该 tag 名被旧 Release 占用 | 换新 tag |
| `run differs from authorized frozen experiment` | 配置/数据/代码版本变了 | 回到冻结版本，别单独改预算 |
| `checkpoint dev replay mismatch` | 权重与日志不匹配或数据管线变了 | 检查是否覆盖了 `best.pt`、统计或划分 |
