# 成员2：B/C/D、方法与最终训练

先读 `00_交接说明_两位成员先读.md`；基线与数据现状见 `docs/交接文档_当前进度与接手说明.md` 与 `docs/G_A正式基线结果与分析.md`。**成员1 已完成 G/A 全部 6 次正式 run（各 3 种子 × 20 epoch）并核验，不要重跑。** 你负责 B/C/D 各 3 种子（9 次）与评估冻结后的最终模型。

1. 完整解压，改动前 `python -X utf8 -m tools.package_team --verify .`，按 README 装环境，跑 21 项自测与 `tools.verify_data_handoff`。读数据审计报告：真实全 JPEG、AI 全 PNG、813 张短边<224，别把随机划分成绩当跨来源泛化。
2. 接续 `cvdetect/`、七组配置与 `docs/模型训练_方法章节草稿.md`。已有共享工程是职责调整前在本聊天完成的，保留历史来源，不追认为你的原创；贡献按真实后续修改登记。
3. 共同预算不变：20 epoch / 224 / width 32 / batch 16 / workers 0 / 种子 17/29/43。先跑 B/C/D 的种子17，再补 29/43，输出新目录 `runs/B_seed17` 等；**不要**用 G/A 的 checkpoint 初始化，也不要给某一组单独加预算或改分辨率。
4. 每 run 保留 config/metadata/environment/metrics/best/last/dev 逐图预测与版本哈希；checkpoint 按 dev Accuracy→较低 BCE→较早 epoch 选择，阈值 0.5。
5. 与 A 对照而不是与 G 对照：A 是局部输入基线（均值 0.8806、标准差 0.0260），B/C/D/E/F 都建立在局部输入上；B/E 与 D/F 必须同容量，所有组共享同样的正常/JPEG 两视图监督，只切换残差分支与 JS 一致性开关。
6. 结果交成员3 汇总；若需方法改进，先写清科学问题、公平对照与须重跑范围，不靠榜单或 holdout 调参。课程禁止预训练。
7. 成员3 交付评估冻结与模型选择摘要后，你执行 `python -X utf8 -m tools.prepare_data refit --evaluation-freeze …` 生成全量有标签清单与统计，再按 `docs/最终重训与结果追溯.md` 训练最终模型；官方 test 与 CSV 由成员3 完成。
