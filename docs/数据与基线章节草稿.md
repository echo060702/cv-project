# 数据与G/A输入基线章节草稿

本项目使用比赛指定的8,000张有标签图像，真实图和AI图各4,000张，标签分别为0和1。逐图审计未发现不可解码文件。数据含RGB、RGBA、灰度和CMYK模式，统一按EXIF方向转正并转换为RGB。

为降低重复图跨集合引起的泄漏风险，我们先对EXIF/RGB后的像素计算哈希，并用固定64位DCT感知哈希筛查汉明距离不超过4的近重复候选，再按家族分层划分。本数据未发现完全重复或命中该筛查条件的候选，最终以固定种子17得到5,600张训练、1,200张开发验证和1,200张保留图像，每部分两类均衡。该有限筛查不保证消除任意裁剪或同来源相关性。数据清单和SHA256随代码交付。

归一化参数只由训练部分估计。每图转换后以双线性插值缩放到128×128，累计等图权重RGB矩，得到均值(0.48354,0.45821,0.40479)、标准差(0.27049,0.26258,0.27667)。数据模块输出未归一化[0,1]张量，模型内部完成归一化。

输入比较包含整图缩放G与原生尺度局部裁剪A，目标尺寸均224。局部输入短边不足时进行对称反射填充；训练使用随机水平翻转及随机位置，开发验证使用中心位置。正常和JPEG视图共享几何变换，在整幅变换图像上以质量60～100重编码后对齐裁剪，避免两视图位置不一致。数据顺序与增强由种子、epoch和图像ID确定，七组实验共用同一实现。

审计发现两类存在明显格式与分辨率偏差：真实图均实际编码为JPEG、AI图均为PNG；813张短边不足224，其中真实313、AI 500。共同JPEG增强不保证去除这些捷径。因此后续评估须结合重编码、尺寸和填充诊断，不能只依据随机划分成绩宣称通用AI图像检测能力。

共同训练配方在正式dev成绩产生前冻结为20epoch、width32、batch16、AdamW学习率0.001和weight decay 0.0001，种子17/29/43。G/A 六次全部跑满并按同一条规则选择checkpoint：G_seed17 0.8042（ep18）、G_seed29 0.8050（ep18）、G_seed43 0.8050（ep20）；A_seed17 0.8708（ep19）、A_seed29 0.9100（ep18）、A_seed43 0.8608（ep19）。三种子均值±样本标准差为 **G 80.47±0.05%、A 88.06±2.60%**，A−G=+7.58个百分点，三个种子上A均更高；A的种子间波动明显大于G。六套checkpoint已重载重放1,200张dev，与日志一致（`results/baselines/baseline_summary.json`）。

需要明确三点边界：其一，dev同时用于checkpoint选择，这些是开发集选择后的成绩，独立结论待成员3冻结方案后的holdout确认；其二，G把整图缩放到224、A在原生分辨率取224局部，两者同时改变视野与尺度，差异不能唯一归因于局部高频信息；其三，真实图全为JPEG、AI图全为PNG且813张短边不足224，共同JPEG增强不保证消除捷径，随机划分成绩不支持跨生成器泛化。B/C/D由成员2完成，E/F和独立评估由成员3完成。

G/A都使用同一随机初始化RGB骨干，参数量均为2,795,297，均接受正常/JPEG两视图监督，不包含辅助分支或JS一致性项。它们比较整图缩放与局部取样两种输入策略。该比较同时改变视野和尺度，不能将观察到的差异唯一归因为高频信息。

每次训练按干净单patch开发集Accuracy选择checkpoint，并列时选BCE较低者，再并列保留较早epoch，分类阈值固定为0.5。三种子完成后给出均值和样本标准差；当前仅两个种子可用于观察趋势。训练曲线中的训练loss是正常/JPEG配对监督损失，开发loss是干净单视图BCE；两者对应不同输入条件。开发集也用于选择checkpoint，其成绩用于方法开发；独立确认由成员3在冻结方案后对holdout完成。
