# 仓库内容、数据与权重获取说明

本仓库用于课程小组协作与可复现交付，只提交**可版本化**的内容；图像与训练权重通过外部来源获取。

## 1. 仓库里有什么

| 路径 | 内容 |
|---|---|
| `cvdetect/` | 模型、损失（含 JS 一致性）、训练器、推理、最终重训入口 |
| `configs/G~F.json` | 七组实验配置，均 `frozen_budget`（20 epoch / 224 / width 32 / batch 16 / workers 0） |
| `team_data.py`、`tools/` | 数据适配器、数据准备、交接核验、基线运行与汇总、打包与审计工具 |
| `tests/` | 21 项自测（含数据管线、checkpoint 恢复、打包清单） |
| `data/splits.csv`、`data/audit/`、`data/statistics.json` | 冻结划分、逐图审计、仅用 train 估计的归一化统计 |
| `data/raw/train_labels.csv`、`sample_submission.csv` | 官方标签与提交模板 |
| `runs/baselines/<exp>_seed<seed>/` | G/A 六次正式运行的 metrics、dev 逐图预测、config、metadata、environment（**不含 .pt**） |
| `results/baselines/` | 六次汇总 `baseline_summary.json`、`per_run.csv`、`summary.csv`、训练曲线 |
| `results/handoff/` | 交接进度快照 |
| `validation/` | 第一/二轮核验报告、数据下载与审计证据、冻结预算（**不含 .pt**） |
| `docs/` | 交接文档、数据审计报告、G/A 结果分析、环境与已知问题、成员接手指南 |

## 2. 获取官方图像（必须）

- 来源：Kaggle 比赛页指定的 Hugging Face 数据集 `emiliiia/ai-generated-image-detection-benchmark`
  （版本 `ab5ac7470f495fff579cc1ebae0962a54cedc40d`，公开可下载）。
- 官方图像包：`dataset.zip`，2,065,749,665 字节，
  SHA256 `3bf72e622a808fbfcb7505ef87dc54e726039a0d6dc7df327cf615cfdb943b38`。
- 解压后放到 `data/official/dataset/train/` 与 `data/official/dataset/test/`，
  目录结构与 `data/audit/images.csv` 中的 `relative_path` 一致。
- 校验：`python -X utf8 -m tools.verify_data_handoff --recompute-statistics --output validation/data_pipeline_report.json`
  应通过；它逐图核对文件哈希、标签、划分与统计。

## 3. 获取 checkpoint

六次正式运行的 `best.pt`/`last.pt`（各 32.5 MB，共约 393 MB）不进入 git，原因：

- GitHub 单文件 100 MB 硬限制，且 LFS 免费额度 1 GB；
- 训练权重属于二进制产物，纳入 git 会永久膨胀历史。

获取方式（任选其一）：

1. 从小组发布的离线交接包 `AI图像识别_数据与GA六次基线_完整交接包_20261122.zip`
   （SHA256 `25ecbd866c71b057c48254ac9da491b3ae0512f5c6fe5a003d27970e50df004b`）解压取得；
2. 由负责人上传到 Hugging Face 模型/数据集仓库或 GitHub Release（Release 单文件上限 2 GB，可放单个 best.pt 包）；
3. 用本仓库代码自行复现（每 epoch 约 2–5 分钟，单次 20 epoch）：

```bash
python -X utf8 -m tools.run_baselines
python -X utf8 -m tools.summarize_baselines --runs runs/baselines --output results/baselines --verify-predictions --device cuda
```

## 4. 复现 G/A 六次结果

```bash
python -X utf8 -m unittest discover -s tests -v          # 21 项自测
python -X utf8 -m tools.run_baselines                    # G17→A17→G29→A29→G43→A43
python -X utf8 -m tools.summarize_baselines --runs runs/baselines --output results/baselines --verify-predictions --device cuda
```

已发布结果（dev 单 patch、阈值 0.5）：G 0.8047 ± 0.0005，A 0.8806 ± 0.0260，A−G = +7.58 个百分点；
详见 `results/baselines/summary.csv` 与 `docs/G_A正式基线结果与分析.md`。

## 6. 推送到 GitHub 的环境问题与做法

本机 git 通过 schannel 访问 HTTPS 会失败：

```
fatal: unable to access 'https://github.com/...': schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030e)
```

这是本机 TLS 后端问题（不是仓库或 token 的问题）。已验证可用 `C:\Program Files\Git\cmd\git.exe -c http.sslBackend=openssl` 绕过。
仓库根目录 `push.ps1` 已封装该后端与分支：

```powershell
$env:GITHUB_TOKEN = "<PAT>"
powershell -ExecutionPolicy Bypass -File .\push.ps1
```

约束：

- 单文件超过 100 MB 会被 GitHub 拒绝；本仓库最大文件约 1 MB，可安全推送。
- 完整离线交接包 2.28 GiB **不能**放进 git 历史，也不适合 LFS 免费额度（1 GB）。需要时用 GitHub Release（单文件上限 2 GB）
  存放权重包，图像走官方 Hugging Face 数据集。
