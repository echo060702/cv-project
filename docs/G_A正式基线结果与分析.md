# G/A 正式基线结果与分析（六次跑满）

更新：2026-11-22 16:28。状态：G/A 各 3 个种子全部跑满 20 epoch，六套 checkpoint 已重载并重放 1,200 张 dev，记录与重放一致。数据：`results/baselines/baseline_summary.json`（passed=true，`checkpoint_predictions_replayed=true`，`holdout_evaluated=false`，`test_pixels_decoded=false`）。

## 1. 口径

- 任务：AI 生成图像二分类（0 真实 / 1 AI），单 patch、阈值固定 0.5。
- 指标：干净 dev 的 Accuracy，附 BCE。dev 同时用于 checkpoint 选择（dev Accuracy → 较低 BCE → 较早 epoch），因此这些数字是**开发集选择后的表现**，不是独立泛化成绩。独立确认由成员3 在方法冻结后对 holdout 完成。
- 共享配方：20 epoch、224 输入、width 32、batch 16、workers 0、AdamW lr 1e-3、wd 1e-4、种子 17/29/43、参数量 2,795,297；G/A 都使用随机初始化单 RGB 骨干与正常/JPEG 两视图监督，不含残差分支、不含 JS 一致性项（`consistency=0`）。

## 3. 三种子汇总

| 实验 | 输入 | dev Acc 均值 | 样本标准差 | dev BCE 均值 | BCE 标准差 |
|---|---|---|---|---|---|
| G | 整图缩放 224 | 0.8047 | 0.0005 | 0.4329 | 0.0060 |
| A | 原生尺度局部裁剪 224 | 0.8806 | 0.0260 | 0.2995 | 0.0492 |

A − G = **+7.58 个百分点**（BCE −0.133）。三个种子上 A 均高于 G：种子17 +6.67、种子29 +10.50、种子43 +5.58 个百分点，方向一致。但 A 的种子间波动（标准差 2.60）远大于 G（0.05），说明局部输入带来了更高的方差；仅 3 个种子，本文不做显著性检验，不把均值差当作已确立效应。

## 4. 成本

参数量与显存完全相同（2,795,297；峰值约 1.94 GB），每 epoch 中位耗时 121–140 s，两组的训练成本处于同一量级，差异主要来自随机波动而非输入方式。G_seed17 日志中 `recorded_epoch_seconds_total` 异常偏大（约 9.2 小时）是暂停期间进程挂起被计入墙钟时间所致，真实单 epoch 见上表中位数；原始值保留不删改。

## 5. 解释边界

1. **G 与 A 同时改变了视野与尺度**：G 把整图压到 224，A 在原生分辨率取 224 局部，因此差异不能唯一归因于"高频细节"或"局部纹理"；要归因需要额外的同区域缩小—恢复诊断或同视野对照。
2. **格式混淆**：审计已发现真实图全为 JPEG、AI 图全为 PNG，且 813 张短边不足 224。共同 JPEG 重编码视图不保证消除原始编码痕迹，随机划分上的成绩不支持跨生成器或跨来源泛化结论。
3. **dev 复用**：checkpoint 在同一 dev 上选择，数字偏乐观；holdout 只在成员3 冻结评价方案后确认。
4. 训练曲线（`training_curves.png/pdf`）中训练 loss 是正常/JPEG 双视图监督损失，dev loss 是干净单视图 BCE，两者输入条件不同，不能直接相减比较。

## 6. 对后续实验的含义

- A 作为更稳的输入基线：其均值更高但方差更大，B/C/D/E/F 都建立在局部输入上，成员2 的改进需要与 A（而非 G）比较才能区分"输入红利"与"方法红利"。
- 由于 G/A 都训练充分（20 epoch，best epoch 多在 18–20），若 B/C/D 相对 A 无收益，应首先怀疑改动本身而非训练不足。
