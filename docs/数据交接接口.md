## config输入

- `data.root`：官方图像根目录；`data.manifest`：冻结清单路径。
- `data.mode`：global/local；`data.image_size`：默认224。
- `data.jpeg_quality`：[60,100]，两类同分布。
- `training.batch_size/workers` 与 `seed`：各组统一。
- 只返回train和dev加载器，不创建官方test加载器，不让holdout参与训练/选择。

## batch约定

| 键 | 内容 |
|---|---|
| image | `[B,3,224,224]` float raw RGB，范围[0,1]，未归一化 |
| image_jpeg | 同形状，配对重编码视图，与image共享几何及裁剪位置 |
| label | `[B]`，0真实、1AI，可浮点或整数，训练器转float |
| image_id | B个唯一图像ID，与manifest一致 |
| group_id | B个重复家族ID，与manifest一致，可在同一split内重复 |

JPEG在整幅变换后的图像上编码再取patch。局部训练随机位置，dev固定中心；整图模式统一缩放。短边不足的填充、全局缩放/配对的精确先后顺序及JPEG库版本，在`data_revision`对应说明中固定。dev.image_jpeg可以保留确定性JPEG，训练器正式dev只读image。

当前冻结为num_workers=0，模块拒绝非0；更改需统一新版本并验证。`set_epoch(epoch)` 必须为0-based epoch重设shuffle generator和增强随机性，使相同(seed,epoch,image_id)获得可复现数据。若另行实现多worker，需在数据模块用顶层worker_init_fn为Python/NumPy播种，并关闭persistent_workers或实现显式epoch传播；需先验证恢复一致性。

## metadata约定

```json
{
  "data_kind": "official",
  "data_revision": "团队为本次真实数据处理分配的版本标识",
  "split_sha256": "冻结清单文件真实字节的64位小写SHA256",
  "mean": [0.5, 0.5, 0.5],
  "std": [0.5, 0.5, 0.5],
  "splits": {
    "train": {"image_ids": ["train_id"], "group_ids": ["train_family"]},
    "dev": {"image_ids": ["dev_id"], "group_ids": ["dev_family"]},
    "holdout": {"image_ids": ["holdout_id"], "group_ids": ["holdout_family"]}
  }
}
```

上面是字段示意，不是可直接使用的正式元数据；mean/std数值必须来自train统计，SHA256必须真实计算。holdout仅交付ID和分组，不将其标签或图像放进训练loader。

清单列固定 `image_id,relative_path,label,group_id,split`，split=train/dev/holdout。入口检查跨split图像ID/分组交集、首批形状范围和标签；它依赖成员1提供的元数据真实可靠，不能代替实际去重审计。首批检查不证明后续所有batch都正确，成员1应完成全数据审计及加载覆盖核验。
